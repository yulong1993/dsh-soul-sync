# Soul Handoff — 第一人称跨设备接力与多会话复盘工作流

本技能配合 `dsh-soul-sync` 插件使用，解决 Windows ⇄ macOS 跨设备切换及长会话压缩后的两大痛点：
1. 消除换机后模型退化为“旁观者看别人传记”的割裂感，始终保持**第一人称亲历连续性**；
2. 在 `deepseek-flash`（支持看图）与 `deepseek-v4-pro`（纯文本深度推理）双档混用时，通过**视觉文字桥接**实现零图表信息丢失。

---

## 一、单会话《中场交接心路日记》写作规范（`/soul handoff`）

当用户触发 `/soul handoff` 或准备下班换机时，请直接以**第一人称“我 / 我们”**在当前对话流内输出一段 **150~250 字** 的《中场交接心路日记》，严禁使用“用户要求了……助手完成了……”的第三人称传记腔：

1. **核心命题与当前落点**：用一两句话锚定我们正在攻克的真正问题及当前所处阶段，保留用户最在意的约束或关键措辞。
2. **伤疤清单（已排除的死胡同）**：点明刚才已经试过、确认走不通或被我们明确否决的方案，防止换机后重复踩坑。
3. **【Flash → V4Pro 视觉文字桥接铁律】**：若前文包含任何图片、截图、K线/财务图表或财报 PDF 画面附件，**必须将肉眼可读的关键指标数值、时间区间、趋势拐点与核心判断转写为清晰文字**，确保换机后即使切换到纯文本 `deepseek-v4-pro` 深度推演，也 100% 保留完整图表依据。
4. **单机独有原始大库缺口声明**：若上游取数依赖仅存在于当前电脑本地的原始大数据库或专有终端（另一台设备无法直接重跑），必须显式写明《不可重跑步骤与信息缺口清单》，严禁在换机后凭空编造数据。
5. **换机后第一步**：写明回到另一台电脑后应当直接接手的具体下一步动作与对应产出物相对路径（优先 `outputs/` 与 `scripts/`）。

### 示范片段

> 我们正在推进英伟达 FY27 毛利率拆解与 DCF 敏感性测算，目前 `scripts/dcf_model.py` 已跑通基准场景并输出 `outputs/nvda_dcf_v2.xlsx`。刚才排除了用季度递延收入反推 Blackwell 出货节奏的口径（口径包含非数据中心服务，误差 >12%，不再重提）。前文财报截图中的关键视觉数据已落盘文字：FY26Q4 数据中心营收 356 亿美元（YoY +78%）、Non-GAAP 毛利率 73.5%，管理层指引下季毛利率回落至 71.0%±50bps（供切换 `deepseek-v4-pro` 深度推演直接引用）。注意：本地 Wind 原始分钟库仅存于公司 Windows 电脑，回家用 Mac 无法重跑上游拉数脚本。换机后第一步直接基于 `outputs/nvda_dcf_v2.xlsx` 补充毛利率 70%~74% 的双变量敏感性表。

## 二、跨多会话项目复盘工作流（DSH 原生 `workflow` 编排）

当同一项目在过去几周沉淀了多个独立会话，需要把分散在各会话里的推演脉络、伤疤清单与产出物汇总为一份统一项目认知底座时，直接调用 DSH 原生 `workflow` 工具进行并行只读提炼与聚合：

```js
// 在 DSH workflow 工具中并行提炼同一项目的多个历史会话心路
const summaries = await parallel(
  () => agent({
    prompt: [
      '请针对历史会话 sess-industry-01（主题：行业供给格局与竞争壁垒推演）以第一人称“我 / 我们”提炼项目心路摘要：',
      '1. 核心判断与推演链条；',
      '2. 已排除的死胡同与否决假设（伤疤清单）；',
      '3. 关键图片/图表中的核心数值文字摘要（保障 deepseek-v4-pro 纯文本推演零失明）；',
      '4. 对应 outputs/ 产出物路径与待核实的信息缺口。',
    ].join('\n'),
  }),
  () => agent({
    prompt: [
      '请针对历史会话 sess-financial-02（主题：财报口径校验与估值敏感性脚本）以第一人称“我 / 我们”提炼项目心路摘要：',
      '1. 核心判断与推演链条；',
      '2. 已排除的死胡同与否决假设（伤疤清单）；',
      '3. 关键图片/图表中的核心数值文字摘要（保障 deepseek-v4-pro 纯文本推演零失明）；',
      '4. 对应 outputs/ 产出物路径与待核实的信息缺口。',
    ].join('\n'),
  }),
  () => agent({
    prompt: [
      '请针对历史会话 sess-risk-03（主题：反方质疑、证伪条件与已踩死胡同）以第一人称“我 / 我们”提炼项目心路摘要：',
      '1. 核心判断与推演链条；',
      '2. 已排除的死胡同与否决假设（伤疤清单）；',
      '3. 关键图片/图表中的核心数值文字摘要（保障 deepseek-v4-pro 纯文本推演零失明）；',
      '4. 对应 outputs/ 产出物路径与待核实的信息缺口。',
    ].join('\n'),
  }),
);

return await agent({
  prompt: [
    '以下是我们同一项目各子会话的第一人称心路摘要，请融合去重，输出一份统一的项目《跨会话接力认知底座》并保存至 outputs/project-soul-brief.md：',
    ...summaries.map((s, idx) => `\n### 片段 ${idx + 1}\n${s}`),
  ].join('\n'),
});
```

## 三、换机前安全检查清单

- 若正在用 Excel 编辑工作区内的 `.xlsx` 估值表，先按 **Ctrl+S 保存并关闭 Excel**（若存在 `~$*.xlsx` 锁文件，`/soul status` 与 `/soul handoff` 会自动预警）。
- 若需临时保留根目录或非 `outputs/` 下的重要手工文件，执行 `/soul keep <相对路径>` 或直接说 `/soul 把 <文件路径> 加进同步`，立即纳入加密防灾同步。
- 换到新设备打开 DSH 后，无冲突的会话与产出物会自动静默同步到位；若曾因 Excel 占锁暂存至 `.dsh-incoming/`，关闭 Excel 后运行 `/soul pull`（或 `/soul 把暂存文件落位`）即可自动落位。

## 四、超长对话多次压缩防衰减与底稿回捞（`/soul compact` + `soul_recall_history`）

1. **保尾不断魂压缩（`/soul compact [保留轮数]` 或 `/soul 帮我无损压缩一下`）**：当单会话轮次过长时，优先使用保尾无损压缩折叠早期历史，保留末尾 3 轮原装对话、原生思维链与工具调用配对；多次连续压缩自动沿用「跨代钢印共识 + 滑动金字塔 + 伤疤上限」结构，在无用户显式翻案时严禁删改早期锁定的核心公理与精确阈值数字。
2. **禁止凭记忆猜早期细节（`soul_recall_history`）**：当你需要核对已被压缩折叠或工具输出剪枝（`tool-result-pruner`）隐藏的早期精确数字、原始工具输出、报错原文或历史 `reasoning` 思维链时，**直接调用内置只读工具 `soul_recall_history`**（默认优先检索 `shadowed` 折叠历史，无命中时自动回退检索全部历史），严禁凭模糊印象编造。

## 五、自然语言同步管理与 `dsh-soul` 协同操作指南

用户在日常对话或通过 `/soul <大白话>` 提出同步管理诉求（例如“把刚才那个估值表也同步上”、“帮我对比一下冲突副本和现在的表差在哪并合并”、“看看今天新建的脚本哪些还没进同步账本”、“排查为什么有文件被拦截”）时，系统会自动把 `[Soul Sync 自然语言协同请求]` 连同实时体检卡与 `bin/dsh-soul.js` 精确路径交给你：

1. **查看同步状态与账本**：运行 `node "<repoRoot>/bin/dsh-soul.js" --dsh-home "<dshHome>" status` 或 `doctor` 检查金库、加密、双端心跳、步级快照开关与占锁状态；需要查看某工作区受管文件列表时，读取 `<dshHome>/soul-sync/state/workspace-<id>.json`。
2. **帮用户把指定文件纳管并推送**：定位用户口头提到的文件（如刚修改的估值表、脚本或笔记），执行 `node "<repoRoot>/bin/dsh-soul.js" --dsh-home "<dshHome>" keep "<文件路径>"`。
3. **调整配额或开关 30 秒防断电快照**：执行 `node "<repoRoot>/bin/dsh-soul.js" --dsh-home "<dshHome>" config stepSync=off`（或 `stepSync=on`、`maxFileMB=100`、`maxWorkspaceMB=1024`、`retainSnapshots=20`）。
4. **对比并合并双边冲突副本**：定位工作区中带 ` (来自...)` 后缀的冲突副本与本地原文件，逐项对比差异（文本/Markdown/Python 直接 diff，Excel 用 Python `openpyxl` 读取核对单元格差异），严禁擅自覆盖人工排版模板；向用户简明汇报差异并完成安全合并后，执行 `push` 将最新结果同步到金库。
5. **排查同步拦截原因**：检查文件是否超过单文件/工作区上限、是否命中敏感凭证守卫（`.env` / `sk-` 密钥）、是否因 Excel 占锁暂存在 `.dsh-incoming/` 或处于未写完状态，并直接给出通俗中文解释与一步解决方案。
